- 작성일: 2026-09-17
- 기준 브랜치: `codex/work46-document-payment-system`
- 목적: 기존 문서결재를 보존하면서 중소기업 운영에 필요한 표준문서 5종을 구조화하고, 구매요청부터 지출결의와 지급 결과까지 연결한다.
- 배포 상태: 검토용 구현 완료, 운영 배포 전

## 1. 구현 범위

표준문서는 다음 5종이다.

1. 지출결의서
2. 구매·수리 요청서
3. 휴가·근태 신청서
4. 일반 품의서
5. 생산·품질 예외처리서

모든 문서는 자동 문서번호, 작성자, 결재선, 상태, 첨부, 처리 이력을 공통으로 가진다. 기존 `document_approval_requests`와 기존 v3 `expense_approval_requests`의 조회·이력은 보존한다. 신규 작성은 `business_documents` 기반 표준 문서에서 수행한다.

## 2. 지출결의 및 구매 연결

- 지출 처리유형: 거래처 지급, 직원 경비 정산, 법인카드·기지급 정리
- 금액: 공급가액과 부가세를 원 단위 정수로 검증하고 합계를 서버에서 계산
- 지급 구분: 지급 전, 일부 지급, 지급 완료, 지급 불필요
- 구매 연결: 승인된 구매요청만 지출결의에 연결
- 구매 승인금액 초과 방지: 연결된 지출결의 합계가 구매 승인금액을 넘으면 제출 차단
- 반려·회수·승인취소: 예약된 구매 연결금액을 원자적으로 반환
- 기지급 정리: 추가 지급을 금지하고 회계의 증빙 정산 완료를 별도로 기록

## 3. 결재 및 지급 통제

- 지출결의: 작성자 → 회계 검토자 → 최종 관리자
- 나머지 문서: 작성자 → 최종 관리자
- 작성자·회계 검토자·최종 승인자의 자기결재 및 동일인 중복 지정 차단
- 현재 지정 결재자만 승인·반려 가능
- 반려 사유 필수, 반려·회수·취소 문서는 이전 문서를 보존한 새 문서로 재상신
- 승인취소는 지급·정산·처리 완료 전만 가능
- 지급은 회계 또는 관리자만 기록하며 승인금액 초과, 미래 지급일, 중복 지급 식별번호를 차단
- 동시 지급 요청도 Firestore 트랜잭션으로 승인금액을 초과할 수 없음
- 지급 증빙 업로드 후 실제 객체의 크기·형식을 서버가 확인해야 지급 기록 확정
- 시스템은 실제 계좌 송금을 실행하지 않고 지급 결과만 기록

## 4. 접근 및 파일 보안

- 표준 문서와 이력·지급 자료는 클라이언트 SDK 직접 읽기·쓰기를 모두 차단하고 callable 서버 경로만 허용
- 요청자, 지정 결재자, 관리자만 일반 문서 열람
- 회계는 지출·구매 문서만 업무 범위로 열람
- 휴가·근태와 생산·품질 문서는 관계없는 회계 계정에서 조회 차단
- 첨부는 등록된 경로·크기·형식과 일치할 때만 업로드
- 제출 후 첨부 덮어쓰기·삭제 금지
- 지급 증빙은 지급 초안을 만든 담당자만 업로드하며 기록 후 덮어쓰기·삭제 금지
- 개인 계정 인증을 요구하고 익명 인증의 표준 문서·첨부 접근 차단
- 계정 전환 시 목록·상세·작성값과 진행 중 응답을 폐기

## 8. 배포 순서와 롤백

운영 반영은 Functions → Firestore Rules → Storage Rules → Pages 순서로 수행한다. 각 단계 성공 후 다음 단계로 진행한다. 운영 데이터 마이그레이션은 없고 새 컬렉션은 첫 표준 문서 작성 시 생성된다. 문제가 발생하면 Pages와 Rules/Functions를 해당 배포 전 버전으로 되돌리며, 운영 문서나 지급 기록을 삭제해 롤백하지 않는다.
