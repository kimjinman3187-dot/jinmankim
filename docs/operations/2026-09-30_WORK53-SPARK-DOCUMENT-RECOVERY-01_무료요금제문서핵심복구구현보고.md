## 장애 원인

표준 문서 화면은 `httpsCallable("businessDocument")`를 호출했지만 운영 Firebase 프로젝트의 Spark 무료 요금제에는 해당 Cloud Function이 배포되어 있지 않았다. 동시에 기존 Firestore Rules는 `business_documents`의 직접 접근을 차단했기 때문에 호출은 `internal`로 끝났고, 화면은 조회 실패를 실제 0건처럼 표시했다.

## 구현 범위

- Cloud Functions 호출을 제거하고 Firebase Web SDK 기반 Firestore 트랜잭션으로 교체했다.
- 지출결의서, 구매·수리요청서, 휴가·근태신청서, 일반품의서, 품질예외보고서의 작성·조회·결재 요청·승인·반려·회수·재상신을 복구했다.
- 문서 상태 변경과 불변 이력을 동일 원자 작업으로 묶었다.
- 첨부파일 메타데이터와 Storage 업로드의 이름·크기·형식·경로를 Rules에서 교차 검증했다.
- 역할, 결재 순서, 요청자/결재자 범위, 불변 필드, 상태 전이를 Firestore Rules에서 강제했다.
- `internal` 원문을 사용자 친화적인 안내로 바꾸고 조회 실패 시 지표를 `0`이 아닌 `—`/`조회 실패`로 표시했다.
- 지급 기능과 지급 증빙 쓰기는 1단계에서 명시적으로 비활성화했다.
- A4 인쇄 전용 레이아웃과 PDF 저장 경로를 유지하고, 출력 시 조작 버튼을 제거했다.
- 결재자 명단이 준비되지 않은 경우 문서 조회는 허용하되 새 문서 작성은 잠그고 초기 설정 안내를 표시한다.

## 보안 설계

- 직접 작성 문서는 `schemaVersion: 5`, `clientMode: spark`만 허용한다.
- 문서 생성·제출·승인·반려·회수는 각 상태 전이에 맞는 이력 문서와 함께 기록해야 한다.
- 요청자, 결재선, 작성 시각, 문서번호 등 핵심 필드의 위·변조를 차단한다.
- 문서 읽기는 요청자, 결재선, 관리자 및 지정된 회계 범위로 제한한다.
- 지급 하위 컬렉션과 지급 증빙 쓰기는 계속 차단한다.
- 전체 `users` 문서를 일반 사용자에게 노출하지 않기 위해 최소 정보 전용 `business_approver_directory`를 사용한다. 이 디렉터리는 관리자만 쓰며 원본 `users`의 이름·역할·상태와 일치해야 한다.

## 사용자 경험 검토

- 오류 배너를 강한 분홍색 면 대신 낮은 채도의 반투명 적색 배경과 명확한 문장으로 조정했다.
- 로딩 실패, 권한 오류, 연결 오류를 구분해 다음 행동을 안내한다.
- 결재자 설정 누락 시 빈 선택 상자를 방치하지 않고 작성 영역을 안전하게 비활성화한다.
- 모바일 360/390/430px와 데스크톱 1440px에서 가로 넘침이 없고, 입력 포커스가 시각적으로 드러나는지 자동 검증한다.
- 지급 기능은 숨겨 현재 복구 범위 밖의 행동을 사용자가 시작하지 않도록 했다.

## 운영 전 필수 확인

`business_approver_directory` 초기 데이터는 이번 코드 작업에서 운영 Firestore에 쓰지 않았다. 운영 배포 승인 시 관리자/회계 결재자의 최소 정보 문서를 별도 승인 범위로 확정하고, Rules 및 정적 파일 배포와 함께 순서를 통제해야 한다. 초기 데이터가 없으면 기존 문서 조회는 가능하지만 신규 작성은 안내 문구와 함께 잠긴다.
