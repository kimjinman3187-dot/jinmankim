## 구현 범위

1. 주문 생산과 재고 확보 생산을 화면과 데이터 구조에서 분리했다.
2. 재고 확보 생산은 계획 → 생산 → 수량 완료 → 품질 확인 → 재고 입고 순서로만 진행한다.
3. 품질 확인된 완제품만 생산계획·현재고·입고원장을 단일 Firestore 트랜잭션으로 갱신한다.
4. 동일 생산계획의 중복 입고를 결정적 입고원장 ID로 차단한다.
5. 영업·회계 사용자의 생산 필드 변경을 차단하고 생산담당자·생산관리자 역할을 구분한다.
6. 재고 화면을 임시 BETA 화면에서 완제품 현재고·안전재고·생산입고 원장 화면으로 전환했다.
7. 테스트 데이터 제외 기준을 생산 차트와 자재 요약에도 동일 적용했다.

## 사용자 화면 보정

- 기존 `Inventory (BETA)`와 `수정중` 덮어쓰기 문구를 제거하고 메뉴명을 `재고`로 통일했다.
- 관리자에게만 재고 생산계획 등록 폼을 표시하고 일반 생산담당자는 조회·공정 처리 중심으로 단순화했다.
- 주문 조회 실패와 재고 생산 화면 시작을 분리해 한 기능의 오류가 다른 업무 화면을 잠그지 않게 했다.
- 부족 재고(0 이하)와 안전재고 이하(0 초과·안전재고 이하)를 구분해 KPI 의미를 명확히 했다.
- 마지막 공정 단계도 완료 체크가 보이도록 주문 출고·재고 입고 단계 표시를 보정했다.

## 기준선에서 확인된 별도 문제

Firestore 전체 회귀는 95건 중 92건이 통과했다. 실패 3건은 `business_documents` Rules 평가식 1,000개 한도 초과이며, 같은 테스트를 변경 전 `origin/main` 별도 체크아웃에서 실행해도 동일하게 3건이 실패했다. 따라서 WORK61 생산·재고 변경으로 발생한 회귀는 아니다.

해당 3건은 다음 후속 작업에서 기존 결재 보안을 약화하지 않는 별도 Rules 최적화 대상으로 다룬다.

- 거래처·계약조건 승인서 초안 및 생성 이력
- 스키마 9 지출결의서 생성
