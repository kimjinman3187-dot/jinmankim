## 1. 문서 목적과 작성 원칙

과거에 없던 예산·담당자·일정을 임의로 만들지 않는다. 기록이 없는 항목은 `기록 없음`으로 표시하며, 향후 2차 개발에서는 착수 전에 확정한다.

## 3. 추진 배경

- 주문, 생산, 회계, 미수금 정보가 분리되면 같은 내용을 반복 확인하고 전달해야 한다.
- 결재문서가 화면 입력에만 머물면 첨부·결재이력·A4 출력의 증빙 기능이 부족하다.
- 생산 실적만 관리하면 재고를 미리 생산해 보유하고 주문에 배정하는 전체 순환을 기록할 수 없다.
- 일반 사용자에게 회계·관리자 필드를 모두 노출하면 화면이 복잡해지고 오조작 위험이 커진다.
- 회사 시스템은 처음 보는 사용자도 용어와 다음 행동을 이해할 수 있어야 한다.

## 4. v1.0 목표

1. 승인된 개인 계정과 역할을 기준으로 필요한 메뉴만 제공한다.
2. 영업 주문부터 생산·출고·회계·미수금까지 동일한 데이터 흐름으로 연결한다.
3. 표준 결재문서를 작성·결재·보완·출력·첨부할 수 있게 한다.
4. 주문 생산과 재고 생산을 구분하고 재고 전체 순환을 불변 원장으로 남긴다.
5. 모바일은 현황 확인, PC는 중요한 변경 업무 중심으로 구성한다.
6. Spark 환경에서 Cloud Functions 의존을 최소화하고 클라이언트 트랜잭션과 Security Rules로 무결성을 보완한다.
7. 더존 ERP 연계는 실시간 양방향 연결보다 검증 가능한 CSV/JSON 내보내기를 우선한다.

## 5. 기능 요구사항 기준선

### 5.1 인증·권한

- Google 인증 후 `users/{uid}`가 존재하고 `status=active`인 사용자만 업무 화면에 접근한다.
- 역할은 `admin`, `sales`, `accounting`, `factory`, `factory_manager`로 구분한다.
- 화면의 버튼 숨김과 Firestore Rules의 쓰기 검사를 함께 적용한다.
- 관리자는 사용자 승인과 전사 업무를 관리하며, 생산관리자는 생산·재고 변경을 담당한다.

### 5.2 영업·회계·미수금

- 주문 작성·조회·승인 상태와 생산 진행을 연결한다.
- 입금은 누적 원장으로 기록하고 취소·정정·중복 동작을 통제한다.
- 계산서 발행, 청구 대기, 수금 대기와 미수금 현황을 확인한다.
- 회계·관리자만 지급과 회계 처리 필드를 변경한다.

### 5.3 결재문서

- 문서 종류: 지출결의서, 구매요청서, 거래처·계약조건 승인서, 휴가신청서, 일반품의서, 품질이슈 보고서.
- 임시저장, 수정, 결재 요청, 승인, 반려, 회수, 보완 요청, 재상신, 승인 취소와 처리 완료 이력을 지원한다.
- 첨부는 파일명·크기·형식·SHA-256·완료 상태를 검증하고 허용된 사용자만 내려받는다.
- A4 요약본에는 문서정보와 결재칸을, 상세본에는 결재·처리이력과 첨부 요약을 포함한다.
- 지출결의서는 과세·면세·영세 구분과 공급가액·부가세·총액 계산을 제공한다.
- 승인된 지출결의서는 UTF-8 BOM CSV 또는 JSON으로 생성하고 실제 ERP 이관 확인을 별도 상태로 기록한다.

### 5.4 생산·재고

- 주문 생산은 주문별 생산수량과 `생산 중 → 수량 완료 → 품질 확인 → 포장 → 출고` 단계를 관리한다.
- 재고 생산은 계획, 생산, 품질 확인, 재고 입고 확정을 분리한다.
- 재고는 현재고, 주문 예약, 출고 가능 수량으로 구분한다.
- `생산입고 → 재고 보유 → 주문 배정 → 출고 → 전량 반품·정정` 순환을 제공한다.
- 재고 이동 원장은 수정·삭제하지 않고 정정 사유가 있는 새 이벤트를 기록한다.

### 5.5 PC·모바일 UX

- 역할별 기본 화면과 메뉴를 다르게 제공한다.
- 모바일 생산·재고는 핵심 현황과 최근 기록을 읽기 쉽게 표시한다.
- 주문 배정·출고·반품·수량 정정은 PC에서만 처리하도록 안내한다.
- 업무 용어는 구현 용어보다 사용자가 바로 이해할 수 있는 한국어를 우선한다.
- 오류 시 내부 코드만 표시하지 않고 다음 행동을 안내하며, 조회 실패를 `0건`으로 오인시키지 않는다.

## 6. 비기능 요구사항

| 구분 | 요구사항 |
|---|---|
| 보안 | 최소권한, 역할 검증, 불변 원장, 서버시각, 허용된 상태 전이 적용 |
| 무결성 | Firestore transaction/batch와 Rules를 함께 사용하고 중복 operation ID를 차단 |
| 사용성 | 처음 보는 사용자가 화면 목적·현재 상태·다음 행동을 한눈에 이해 |
| 심미성 | B2B 업무 화면에 맞는 정렬·여백·글자 크기·카드 밀도 유지 |
| 인쇄 | 표준 결재문서는 A4 한 페이지 요약 또는 상세 PDF로 출력 가능 |
| 호환성 | PC Chrome/Edge 중심, 모바일 조회 화면 지원 |
| 복구성 | 모든 변경은 Git PR로 기록하고 운영 데이터 정리 전 복구본 확보 |
| 비용 | Spark 제약 안에서 운영하며 유료 서비스 전환은 별도 승인 |

## 7. 제외 범위와 후속 과제

### v1.0 제외 또는 후속 운영 검증

- 실제 생산·생산관리자 계정 생성과 계정별 1회 로그인 점검
- 회사 더존 ERP의 실제 업로드 열 규격과 UTF-8 BOM/EUC-KR 인코딩 확정
- 실제 사용자의 휴대폰·PC 현장 사용성 확인
- 더존 ERP 실시간 양방향 API 연동
- 신규 기능 또는 구조 변경

위 항목은 v1.0 기능 미완료가 아니라 현장 환경에서 확정할 운영 검증 또는 Phase 2 후보다.
