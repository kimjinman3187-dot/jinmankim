# WORK63 생산·재고 전체 순환 구현 및 검증 보고

## 1. 작업 목적

완제품이 생산된 뒤 재고로 입고되고, 주문에 배정되어 출고되며, 취소·반품·재고 실사 차이를 원장으로 정정하는 전체 순환을 하나의 사용자 흐름으로 완성한다.

`생산입고 → 재고 보유 → 주문 배정 → 출고 → 반품·정정`

## 2. 구현 결과

- 생산입고: 품질 확인을 통과한 재고 생산분만 완제품 재고에 원자적으로 입고한다.
- 재고 보유: 현재고, 주문 예약수량, 실제 출고 가능한 가용재고를 분리해 표시한다.
- 주문 배정: 승인·완료 주문과 완제품을 선택하고 가용재고 범위 안에서 예약한다.
- 출고: 배정된 수량만 출고하며 현재고와 예약수량을 동시에 차감한다.
- 배정 해제: 출고 전 취소는 현재고를 바꾸지 않고 예약수량만 복원한다.
- 반품: 출고 완료 건은 전량 반품 입고로 현재고를 복구한다.
- 재고 정정: 실사 차이·오입력 사유를 필수로 받아 증감 원장을 남긴다.
- 이동 원장: 생산입고·배정·출고·배정 해제·반품·정정을 삭제 불가 이력으로 보존한다.

## 3. 사용자 화면 검토

- 작업 순서를 `1. 주문에 재고 배정 → 2. 배정·출고 대기 → 3. 최근 출고·반품`으로 고정했다.
- 데이터가 없을 때도 사용자가 다음 행동을 알 수 있도록 각 영역에 빈 상태 문구를 표시한다.
- 재고 표는 `현재고 / 예약 / 가용 / 안전재고`를 나란히 보여 숫자의 의미를 구분한다.
- 재고 실사 정정은 평상시 화면 부담을 줄이기 위해 접기·펼치기 영역에 둔다.
- 생산관리자만 처리 버튼을 보고, 그 외 사용자는 조회 중심 화면을 보도록 역할을 구분한다.
- 좁은 PC 화면에서 상태 배지가 두 줄로 꺾이지 않도록 한 줄 유지와 축소 방지를 적용했다.
- 로컬 PC 화면에서 제목, KPI, 순환 처리 폼, 빈 상태, 재고 표, 이동 원장을 시각 확인했다.

## 4. 데이터·Rules 안전장치

- `currentQty >= reservedQty >= 0`
- `availableQty = currentQty - reservedQty`
- 모든 수량 변화는 Firestore 트랜잭션으로 재고 문서와 이동 원장을 함께 기록한다.
- 재고 문서의 `lastMovementId`와 같은 트랜잭션의 이동 원장을 상호 검증한다.
- 배정·출고·해제·반품은 배정 문서 상태와 이동 원장 상태를 함께 검증한다.
- 재고 정정은 생산관리자 권한, 필수 사유, 서버 시각, 불변 이동 원장을 요구한다.
- 이동 원장의 수정·삭제는 허용하지 않는다.
